# المنيو الإلكتروني — بصمة ديزاين

هذه حزمة تأسيسية مهيأة لاستخدام قاعدة D1 الحالية `basma-menu-db` بأمان: ملف `schema.sql` ينشئ جداول منفصلة بأسماء `menu_*` ولا يحذف الجداول القديمة. ينقل بيانات المطعم والأقسام والمنتجات إلى الجداول الجديدة دون تعديل جداول المصدر، مع الحفاظ على المعرّفات الأصلية لربط الأقسام بالمنتجات.

## قبل النشر
1. افتح D1 > `basma-menu-db` > Console/SQL، ونفّذ محتوى `schema.sql` مرة واحدة. راجع أي خطأ قبل المتابعة؛ لا تكرر الاستعلام إذا فشل في منتصفه دون مراجعة.
2. من إعدادات قاعدة D1 انسخ Database ID، ثم ضعه في `wrangler.toml` بدل `REPLACE_WITH_YOUR_D1_DATABASE_ID`.
3. لا تنشر قبل نجاح تنفيذ `schema.sql` ومراجعة الجداول الجديدة. إعدادات النشر تعتمد على ربط GitHub وCloudflare، وقد تحتاج ضبط أمر البناء/النشر بحسب طريقة الاستضافة المختارة.
4. أضف Secret باسم `OWNER_BOOTSTRAP_TOKEN` إلى إعدادات Worker، بقيمة طويلة وعشوائية. لا تضع كلمة السر أو هذا الرمز في ملفات GitHub.
5. بعد النشر، أنشئ حساب المالك بطلب POST إلى `/api/bootstrap-owner` مع `Authorization: Bearer <OWNER_BOOTSTRAP_TOKEN>` وجسم JSON مثل `{"username":"basmaadmin","password":"كلمة-مرور-طويلة-جدا"}`. احذف/غيّر السر بعد إنشاء المالك.

## تنبيهات صريحة
- هذه نسخة تأسيسية للاختبار وليست اعتمادًا إنتاجيًا نهائيًا.
- واجهة الموقع الحالية تسمح بعرض المنيو وتسجيل الدخول فقط؛ لوحة الإدارة الكاملة تحتاج استكمال واجهة إدارة المطاعم والأقسام والمنتجات والطلبات.
- الدفع الإلكتروني غير مفعل. الطلبات تدعم الدفع النقدي فقط حتى ربط بوابة دفع حقيقية والتحقق من إشعارات الدفع من الخادم.
- رفع الصور المباشر يحتاج ربط Cloudflare R2 أو خدمة تخزين صور. حاليًا يقبل المنتج رابط صورة.
- يجب اختبار نسخة قاعدة البيانات بعد تشغيل SQL، لأن نقل البيانات يفترض وجود الأعمدة الموضحة في الجداول الحالية.


تنبيه رفع من الهاتف: هذه الحزمة مسطّحة، والملفات في جذر المستودع حتى لا تحتاج إلى رفع مجلدات. عدّل database_id في wrangler.toml قبل النشر. لا تنفذ schema.sql على قاعدة البيانات الحالية قبل مراجعة توافق الأعمدة. هذه الحزمة ليست جاهزة للإنتاج قبل ضبط قاعدة البيانات واختبار الواجهة والـ API.
